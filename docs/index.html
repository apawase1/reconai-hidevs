🚀 FUTURE SCOPE — Planned Integrations

This hackathon build is deliberately scoped to one Gmail inbox + one bank statement per run, to keep API/compute usage inside budget — not because the rest is unbuilt. The tool-layer logic for all four of these already exists and is designed to extend this way with more headroom.

📂 Google Drive discovery

Scan Drive for receipts/invoices saved outside Gmail — downloaded PDFs, scanned bills — so Discovery isn't limited to what arrived by email.

📊 Google Sheets sync

A persistent ledger that remembers what's already been reconciled across runs, and lets the Reporting Agent answer questions across multiple months, not just this run.

🔗 Cross-account reconciliation

Match transfers between a user's own accounts (personal + business current, or a co-founder's inbox) instead of double-counting them as spend — mocked up below.

📈 Growth-strategy synthesis

Month-over-month spend-trend deltas, a cash-flow view netting spend against income, and reinvestment nudges — needs the Sheets ledger above for multi-month history.

Cross-account reconciliation Roadmap — not in this build

Today's build reconciles one Gmail inbox against one bank statement CSV per run. A small-business owner usually has more than one account (a personal account, a business current account, sometimes a co-founder's inbox) — the mockup below is the target shape: transfers between a user's own accounts get matched and excluded from spend entirely, instead of looking like two unrelated transactions. Not to be confused with the "Business vs personal" split above — that's a per-transaction tag within one account/inbox and is live in this build; this panel is about matching transactions across separate accounts, which isn't built yet.
